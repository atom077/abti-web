# PLAN.md — ABTI「AI 时代人类迷惑行为图鉴」产品改版执行计划

> 目标：把当前偏正经的 ABTI 人格测试，升级为更适合社媒传播的「AI 时代打工人 / 协作人格 / 迷惑行为图鉴」版本。  
> 核心原则：结果要让用户产生「笑死，这不就是我」「怎么骂人还挺准」「我要发给朋友/同事」的分享冲动。

---

## 0. 项目背景

当前 ABTI 已经完成基础设计与上线，但现版本偏严肃、偏正向人格分析，传播钩子不足。

本次改版不是单纯换 UI 或改几句文案，而是重构 ABTI 的产品表达：

- 从「AI 时代协作性格分析」
- 改为「AI 时代人类迷惑行为图鉴」
- 从「测你是谁」
- 改为「测你在 AI、需求、协作、DDL 面前怎么发疯」

保留 ABTI 品牌名，但重新解释为：

```txt
ABTI = AI Behavior Type Indicator
中文名：AI 时代人类行为类型指标
传播名：AI 时代人类迷惑行为测试
```

---

## 1. 改版目标

### 1.1 产品目标

用户完成测试后，结果页应该具备以下传播感：

1. 标签鲜明：用户一眼知道自己是哪类人。
2. 半夸半损：既有共鸣，也有槽点。
3. 截图友好：结果卡片适合发小红书、朋友圈、群聊。
4. 可讨论：用户愿意把结果发给朋友，让对方也测。
5. 可对比：不同人格之间有「最佳队友 / 协作天敌 / 危险组合」。

### 1.2 技术目标

在不大规模推翻现有项目的前提下，完成：

- 首页定位文案改版
- 测试题文案改版
- 人格类型数据结构改版
- 结果页结构改版
- 毒舌版/正常版切换
- 分享卡片生成或截图优化
- 兼容现有部署环境

## 3. 人格维度设计

本版本建议使用 4 个行为维度，每个维度 2 个方向，组合出 16 种人格。

### 3.1 维度 A：面对 AI

```txt
D = 驾驭型 Driver
我用 AI 放大能力，喜欢控制方向、拆任务、调 Prompt。

R = 依赖型 Reliant
AI 不回我，我不会开工；喜欢让 AI 先给方向、给参考。
```

### 3.2 维度 B：面对任务

```txt
S = 结构型 Structured
先拆流程、定框架、列步骤，再执行。

I = 灵感型 Inspired
先动手、先试错、先乱搞，搞着搞着就通了。
```

### 3.3 维度 C：面对协作

```txt
C = 同步型 Collaborative
喜欢沟通、对齐、推进，重视共识。

L = 单刷型 Lone-wolf
能自己搞就自己搞，讨厌无效会议和反复确认。
```

### 3.4 维度 D：面对结果

```txt
P = 交付型 Pragmatic
先上线，后优化；先解决问题，再追求完美。

M = 打磨型 Meticulous
再改一下、再润色一下、再检查一下，直到看着顺眼。
```

## 5. 结果页信息架构

结果页不要只输出普通分析，建议固定为 8 个模块。

### 5.1 顶部人格卡

包含：

- 人格名称
- 人格 code
- 一句话定义
- 精神状态标签
- 主视觉人物图

示例：

```txt
你是：提示词炼丹师 DSCP
AI 时代精神状态：稳定炼丹中
你不是在使用 AI，你是在驯服一只不稳定的电子神兽。
```

### 5.2 典型症状

标题：

```txt
你的典型症状
```

示例：

```txt
- 一个问题能问 AI 八种版本
- 总觉得“再优化一下 Prompt 就能封神”
- 收藏了一堆提示词模板，但真正用的时候还是现编
- 经常对 AI 说：“不是这个意思，你再理解一下”
```

### 5.3 隐藏优势

标题：

```txt
你的隐藏优势
```

示例：

```txt
你擅长把模糊想法变成可执行路径，是团队里的认知翻译器。
```

### 5.4 职场副作用

标题：

```txt
你的职场副作用
```

示例：

```txt
容易把简单问题搞成一套方法论，让同事怀疑你是不是偷偷报了咨询公司培训班。
```

### 5.5 AI 使用姿势

标题：

```txt
你的 AI 使用姿势
```

内容分为：

```txt
适合用 AI 做：
- 拆解任务
- 生成方案
- 对比选择
- 压缩信息

不适合用 AI 做：

- 替你判断老板到底什么意思
```

### 5.6 灵魂台词

标题：

```txt
你的灵魂台词
```

示例：

```txt
“我不是不会做，我只是想先让 AI 给我 3 个方向。”
```

### 5.7 协作关系

标题：

```txt
你的协作关系
```

包含：

```txt
最佳队友：
- 线上火灾消防员
- 收到马上改战士

协作天敌：
- 感觉不对鉴定师

```

### 5.8 分享卡片

## 6. 毒舌版 / 正常版切换

### 6.1 功能目标

结果页新增切换控件：

```txt
正常版 / 毒舌版
```

默认可以使用「毒舌版」，但要避免真正冒犯用户。

### 6.2 文案原则

毒舌版不是攻击用户，而是「温柔精准地吐槽」。

示例：

正常版：

```txt
你是一个擅长系统化思考的人，喜欢先建立框架，再推进执行。
```

毒舌版：

```txt
你不是不想开始，你只是想先画一张宇宙级架构图来证明自己很忙。
```

### 6.3 实现建议

数据层为每个人格准备两个 summary 字段：

```ts
normalSummary: string;
roastSummary: string;
```

UI 层通过状态切换：

```ts
const [mode, setMode] = useState<'normal' | 'roast'>('roast');
```

## 7. 测试题改造建议

题目不要像传统心理测试，要像真实工作场景。

### 7.1 题目风格

每道题给一个场景，提供 4 个选项，每个选项映射到不同维度分数。

示例：

```txt
老板说：“这个需求很简单，你看着做一下。”

A. 先让 AI 帮我拆解隐藏需求和风险点
B. 先做一个能跑的版本，边做边补
C. 先问清楚目标、边界、验收标准
D. 先沉默 10 秒，因为“很简单”通常不简单
```

### 7.2 建议题目数

推荐：

```txt
12 题
```

原因：

- 少于 8 题会显得太轻
- 多于 16 题会降低完成率
- 12 题比较适合社媒传播

### 7.3 评分逻辑

每个选项增加对应维度分数，例如：

```ts
type Option = {
  text: string;
  scores: {
    D?: number;
    R?: number;
    S?: number;
    I?: number;
    C?: number;
    L?: number;
    P?: number;
    M?: number;
  };
};
```

最终每组维度取高分：

```txt
D vs R
S vs I
C vs L
P vs M
```

组合成 code，例如：

```txt
DSCP
```

## 15. 最终目标

ABTI 不应该只是一个人格测试，而应该成为一个可以传播的自嘲标签系统：

```txt
不是为了告诉用户“你是谁”，
而是让用户忍不住说：
“笑死，这不就是我？”
```
