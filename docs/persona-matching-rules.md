# AI 时代人物图鉴匹配规则

当前版本没有接入 LLM，也不会读取用户日常聊天原文。人物图鉴结果完全由浏览器本地规则生成，核心流程是：

1. 用户回答结构化问卷。
2. 可选填写脱敏后的常用提示词样本。
3. 前端规则引擎计算 14 个 ABTI 内部类型分数。
4. 将 ABTI 内部类型映射到 10 张「AI 时代人物卡」。
5. 聚合人物卡分数，生成主卡、副卡、匹配度和解释文案。

## 输入来源

### 结构化问卷

问卷是当前评分的主要来源。每个选项都带有一组 ABTI 类型权重，例如：

```ts
{
  label: "写清背景、目标、格式",
  weights: { CTRL: 4, NERD: 2 }
}
```

用户选择该选项后，`CTRL` 加 4 分，`NERD` 加 2 分。所有题目的选项权重累加后，得到 14 个 ABTI 内部类型的基础分。

### 自由文本关键词

自由文本不会被发送到服务端，也不会做语义理解。当前只在本地用正则关键词做轻量加权。

例子：

```ts
{ pattern: /依据|证明|推理|逻辑|严谨|可复现|边界|假设/g, code: "NERD", score: 3 }
{ pattern: /快点|赶紧|直接给|别废话|少废话|立刻|马上/g, code: "WHIP", score: 3 }
{ pattern: /vibe|手感|感觉|原型|demo|界面|视觉|交互/g, code: "ROLE", score: 2 }
```

同一条规则最多按 4 次命中计分，避免用户重复输入同一个词导致分数失真。

### 文本长度补正

自由文本长度也会轻微影响评分：

- 超过 700 字：`PILE +4`、`SOUL +2`，表示用户愿意用大量上下文换深度分析。
- 1-79 字：`IDC +2`，表示用户偏好低负担、少输入的测试体验。
- 没有填写自由文本：不做额外加权。

## ABTI 内部类型

当前规则引擎先计算 14 个 ABTI 内部类型：

| 类型代码 | 类型名称 | 行为倾向 |
| --- | --- | --- |
| CUSS | 暴躁老哥型 | 高压纠错，低容忍低质量输出 |
| PILE | 废料堆积型 | 输入大量碎片，让 AI 重组秩序 |
| NERD | 技术洁癖型 | 追求逻辑、依据、边界和可验证性 |
| CTRL | 掌控导演型 | 强流程、强格式、强验收 |
| HIRE | 雇佣专家型 | 把 AI 当顾问、教练或专家团队 |
| ROLE | 角色扮演型 | 用角色、场景和语气打开问题 |
| MASK | 情绪伪装型 | 克制表达，把真实需求包装得体面 |
| IDOL | 赞美驯化型 | 通过正反馈维持协作氛围 |
| SOUL | 灵魂倾诉型 | 把 AI 当作自我理解和情绪镜子 |
| CULT | 神谕膜拜型 | 对“被说中”的洞察感高度敏感 |
| JAIL | 越狱黑客型 | 关注规则、限制和系统边界 |
| WHIP | 鞭打压榨型 | 强结果导向，追求快速交付 |
| FORK | 平行宇宙型 | 喜欢多版本、多路线和分支推演 |
| IDC | 随便躺平型 | 低指令负担，希望 AI 自动补全 |

主型是分数最高的 ABTI 类型，副型是分数第二高的 ABTI 类型。

## 人物卡映射

人物图鉴不是直接从问卷中独立评分，而是由 ABTI 内部类型映射得到。当前映射如下：

| ABTI 类型 | AI 时代人物卡 |
| --- | --- |
| CULT、FORK | 01 灵感捕手 / IDEA HUNTER |
| PILE、CTRL | 02 策略棋手 / STRATEGIST |
| NERD | 03 深度研究员 / DEEP RESEARCHER |
| HIRE、MASK | 04 连接者 / CONNECTOR |
| WHIP | 05 创作猛匠 / CRAFTSMAN |
| ROLE、JAIL | 06 自由探索家 / EXPLORER |
| CUSS | 07 数据洞察者 / DATA INSIGHTER |
| SOUL | 08 价值守护者 / GUARDIAN |
| IDOL、IDC | 09 学习成长者 / GROWER |
| 暂未映射为主结果 | 10 未来架构师 / FUTURIST |

说明：10 张人物卡是对外展示层，14 个 ABTI 类型是内部行为评分层。多个 ABTI 类型可以映射到同一张人物卡，因为它们在用户感知上可能呈现为同一种外显角色。

## 匹配度如何计算

### 主卡匹配度

结果页主卡右上角显示的百分比来自 ABTI 规则引擎的 `confidence`：

```ts
confidence = min(
  96,
  round(42 + answeredCount * 5 + min(freeTextLength / 35, 18) + topGap * 2)
)
```

其中：

- `answeredCount`：已回答题目数量。
- `freeTextLength`：自由文本长度。
- `topGap`：第一名 ABTI 类型分数与第二名 ABTI 类型分数的差距，最低按 1 计算。
- 最高限制为 96，避免给出绝对确定的判断。

这个百分比表示“当前输入对主型判断的稳定程度”，不是 LLM 语义相似度。

### 人物卡匹配度列表

结果页的「人物卡匹配度」会把所有 ABTI 类型分数按人物卡映射聚合：

```ts
cardScore[cardId] += max(0, abtiTypeScore)
percent = round(cardScore[cardId] / totalCardScore * 100)
```

例如 `CULT` 和 `FORK` 都映射到「灵感捕手」，那么这两个 ABTI 类型的分数会合并到同一张人物卡下。

## 当前方案的边界

当前规则更像“可解释的问卷评分器”，而不是完整人格分析模型。

- 不会读取用户历史对话。
- 不会调用 LLM 做语义理解。
- 不会基于真实聊天语境识别反讽、上下文和长期行为模式。
- 自由文本只做关键词和长度加权，无法理解复杂表达。
- 人物卡映射是人工设定的产品设计规则，不是统计训练结果。

## 未来接入 LLM 后的建议

如果后续接入 LLM，建议保留当前规则引擎作为基线，再增加一层语义分析：

1. 规则引擎先给出 ABTI 基础分和可解释证据。
2. LLM 只分析用户主动提交且已脱敏的文本，不读取聊天历史。
3. LLM 输出结构化补充分数、证据句和不确定性。
4. 最终结果合并规则分与 LLM 语义分，仍展示“为什么得到这个人物卡”。
5. 高风险或敏感输入必须提示用户脱敏，并明确是否保存数据。

推荐未来接口形态：

```ts
POST /api/analyze-abti
{
  answers: Record<string, string>;
  freeText: string;
  ruleScores: Record<AbtiCode, number>;
}
```

后端返回：

```ts
{
  semanticScores: Record<AbtiCode, number>;
  evidence: string[];
  uncertainty: string[];
  summary: string;
}
```

这样既能保留当前规则的透明性，也能让 LLM 提供更贴近真实表达的个性化洞察。
